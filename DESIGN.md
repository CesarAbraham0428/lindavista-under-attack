# Design System: LINDAVISTA: UNDER ATTACK

## Overview

Existing Unity cartoon UI uses cream lettering, dark ink and frames, wood signage and gold accents. Game health uses red. This extraction preserves the established art and UI; it introduces no visual system changes.

Source authority: Assets/_Project/Scripts/CartoonUI.cs, ProgressionUI.cs, BossIntroduction.cs and BossHealthHUD.cs; Interfaz/AreaSeguraUI.cs; and Docs/Level4.md. Colors above serialize the source Unity Color channels as exact percentage equivalents for interchange. Unity source remains authoritative; these are not CSS implementation instructions.

## Colors

Cream and ink come from CartoonUI.Cream / Ink; the brown frame border is generated by CartoonUI.FrameSprite. ProgressionUI supplies its dark panel and gold. WoodSign is an existing texture, not a flat color token; dialogue-wood-frame is the cinematic frame tint.

Green belongs to CartoonUI.ButtonStyle. The dialogue and boss HUD have their own dark panel tints. Health red fills the boss health track; the warm attack-warning tint marks warning/firing text. These component colors do not define new global brand roles.

## Typography

CartoonUI loads Resources/UI/LilitaOne and applies FontStyle.Normal when available. ProgressionUI.Text initially uses built-in LegacyRuntime.ttf in Bold; CartoonUI.Typography replaces it when LilitaOne loads. Headings add an ink Outline at effectDistance (2, -2).

Observed Level 4 nominal Unity font sizes: dialogue 50 with lineSpacing 1.1; boss sign 47; chapter 33; time and continuation 30; sentence counter 27. Its label helper allows best-fit down to 22. Boss HUD sizes are title 29, value 25 and status 21, with ProgressionUI's best-fit minimum 12. These are component settings, not a universal type scale or physical-pixel sizes.

## Layout

ProgressionUI.Canvas creates ScreenSpaceOverlay canvases with CanvasScaler ScaleWithScreenSize, referenceResolution (1920, 1080) and ScreenMatchMode.Expand. RectTransform anchors provide proportional layout. AreaSeguraUI normalizes Screen.safeArea and reapplies it when resolution or safe area changes. Both Level 4 components create safe-area content roots; the cinematic dimmer and bands cover the full canvas.

The approved Level 4 composition in Docs/Level4.md keeps the portrait right and dialogue/sign left. Current portrait crop anchors span (0.49, 0.09) to (1, 0.935); dialogue frame spans (0.022, 0.13) to (0.58, 0.425). The boss HUD spans (0.27, 0.025) to (0.73, 0.128) of its safe-area root. These are local screen settings, not global layout rules.

Unity render captures are not actual Android-device proof. Safe-area code and Editor layouts alone do not establish device legibility, touch ergonomics or performance.

## Elevation & Depth

CartoonUI.Frame applies a Unity UI Shadow: black alpha 0.5, effectDistance (0, -6). The cinematic uses a black alpha 0.5 dimmer and black letterbox bands. These are Unity effects and layering, not CSS shadows.

## Shapes

CartoonUI.FrameSprite generates a 64 x 64 texture with a rounded contour using radius parameter 12, dark border tests and a 16-unit sprite border for sliced rendering. CartoonUI.Frame sets Image.Type.Sliced. The texture geometry does not establish a universal screen-space corner radius. The portrait uses RectMask2D cropping with preserveAspect enabled; it is enlarged without stretching or redrawing the face.

## Components

Cartoon buttons use the green sliced frame and cream outlined label. ButtonStyle defines a ColorBlock with normal/selected white, highlighted (1.12, 1.12, 0.95), pressed (0.76, 0.82, 0.63), disabled (0.55, 0.53, 0.45, 0.9), multiplier 1 and fadeDuration 0.12 seconds. These are Unity tint multipliers, including values above 1, not additional flat palette colors.

BossIntroduction reuses WoodSign and the supplied original portrait. Four complete sentences advance through click/tap/Space/Enter; overlay HUD canvases are hidden and restored. The final held pointer is released before restoration. The generated composition remains a reference, not shipped background art.

BossHealthHUD uses a dark sliced frame, red health fill, numeric health and phase/status text. It hides for death, match end, pause and the open shop. These descriptions reflect source behavior, not a new runtime verification.

## Do's and Don'ts

- Do reuse the Unity canvas, safe-area, typography and frame helpers.
- Do keep the original Boss_Base PNG and metadata intact; use the generated composition only as reference.
- Do treat Unity render captures as Unity evidence, not actual Android-device proof.

- Don't translate virtual Unity layout units into CSS pixels or impose HTML components.
- Don't invent palette ramps, typography scales, breakpoints or branding promises.
- Don't edit gameplay scripts, global source, scenes, art or metadata for this documentation handoff.
